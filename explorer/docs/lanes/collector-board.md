# Lane collector-board

Files: `collector/extract/board.py` (record board-files, `board/index.json`, `board/plan-<side>.svg`), tests `collector/tests/collector-board/test_board.py` (10).

What it does: no `design/ecad/ring/*.kicad_pcb` exists, so `routed` is false and `missing` names `design/ecad/ring/ring.kicad_pcb`. The plan comes from the rows of layer `board` of `design/mech/thin/placement.csv`: the largest row is the outline (its line is the outline source), the others are parts. A part is on `top` or `bottom` by where its middle sits against the board's middle, only when it is within BOARD_SIDE_MM of a board face; a farther part is not placed and is named in `missing`. `x`, `y` are the CENTRE of each rectangle, design mm (x along the finger, y + thumb). `part_id` is `ring:<ref>` when the ref is in `design/bom.csv`, else null.

Notches (additive optional field `notches`, added to `contract/schema/board-files.schema.json`, `npm run gen:types` run once): read from the sentences "notch of the board, W x H mm, at the hand-end corner" and "notch of W x H mm on its thumb-side edge" of `design/architecture.md` (the LAST matching line wins, as later sections win); each carries its source line. The corner notch sits flush in the corner on the side of the part whose note says it stands in a notch. The edge notch's place along the edge is not stated anywhere: it is drawn centred, `position_known` is false and `missing` says so.

Board file (read first when present): `design/ecad/ring/*.kicad_pcb` and `design/ecad/ring/pcb/*.kicad_pcb`. `routed` is true only when the file holds tracks (segment, arc or via). The outline is the bounding box of everything on Edge.Cuts; the placed parts are its footprints (reference, position, size from the courtyard else the pads, side from the footprint's layer: F.Cu = top, B.Cu = bottom), all in the FILE's coordinates (KiCad's y points down; centre of the board is wherever the file puts it, not at the origin of `placement.csv`). `part_id` is `ring:<ref>` when the ref is in `design/bom.csv`. When a board file gives an outline or footprints, the placement table and the notches of `architecture.md` are NOT used: the notch rectangles are worked out in `placement.csv` coordinates and would be drawn in the wrong place; the real notches are part of the outline the file draws. Pictures: the real `kicad-cli` (found as `collector/extract/schematic.py` finds it: `$KICAD_CLI`, the two KiCad app paths, then PATH), `pcb export svg --mode-single` with only `Edge.Cuts`, `F.Cu` (pads), `F.CrtYd` (part outlines), `F.Fab` (reference text) for `top.svg`, the `B.*` layers with `--mirror` for `bottom.svg`; no silkscreen, no value text (the file hides values). The file's footprints carry two reference texts on the fabrication layer, so each reference shows twice, small. Checked on the live file on 2026-11-10: 100 footprints, all 100 on F.Cu, none on B.Cu, so all 100 placements are `top` and `bottom.svg` shows the board edge only (an empty back is the truth, not a failure). No tool found: no pictures, said in the manifest message. Tested with a small hand-written board file (two footprints, an outline, no tracks) through the real tool.

Without a board file: SVG one file per side that has parts (`plan-top.svg`, `plan-bottom.svg`; the other side is `null`), a plan seen from above the top face, thumb side up, titled "Planned placement, not routed", with each part's reference.

Departures: none from the contract. The brief's acceptance (27.0 x 17.4, both sides non-empty, 'mic1') belongs to design A3; the placement table gives 27.2 x 12.6, bottom only.
