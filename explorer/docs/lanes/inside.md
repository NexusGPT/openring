## What the screen does (earlier rounds, still true unless layout C above says otherwise)
- Renders only into the shell's panel. Steers the shared stage with `useStageScene({show:'internals', explode, isolatedLayer})`; mounts no stage.
- One control: the slider "Open it up" (native range, 0..1, step 0.02; ArrowLeft/Right move it). The value goes to the stage `explode`.
- Search over the ring's parts-list lines: refs, item, maker, maker part number, the note (`what`, `why`). Folded (case, accents), plain substring (never a RegExp), at most 8 (`MAX_RESULTS`), exact reference first. Enter takes the highlighted row; ArrowUp/Down move it.
- Card: `PartCard` (route `inside`) for `?part=<id>`; `?object=<3D name>` shows "no parts-list line for this object" (see Gaps 1).
- Layers: one row per layer of `part-placements.layers` in record order, count = placed parts in it. A click isolates the layer on the stage and lists its objects (named by the parts-list item plus its reference); a second click or "All layers" shows the ring again. Choosing an object selects its part.
- States: one banner per distinct state of the five records it reads (ring-model, part-placements, parts, files, area-states) plus the notes file, in the contract's words; a stale record dims the whole screen (`data-dimmed`) and keeps it on screen; the panel is never empty (heading, slider, search, hint, layer list with "No layers to show yet.").

## Choices
- Kit read: `docs/CHOOSING.md` and `docs/MOTION.md` (and the `catalog.json` entries). Native controls kept, one line each on why the kit's one does not fit:
  - Slider "Open it up": the kit's `slider` is a vendored shadcn/Radix component styled by Tailwind utility classes and the kit theme; this app has no Tailwind and S1 is square with its own tokens, so it would render unstyled or round. A native range already gives the arrow keys the check needs.
  - Search field: `CommandSearch` and `command` are the same Tailwind/kit-theme family and bring a command-palette look (hint chip, grouped actions); we need one plain field with a folded substring match, at most 8 rows and Enter to select.
  - Layer rows and object rows: plain buttons; the kit has no list of this shape (table and kanban views are for records, not a six-row stack).
  - Motion: the stage eases; the screen adds only a 120 ms colour/transform transition (`--t-fast`, same as the kit's fast step) and the global reduced-motion rule in primitives.css turns it off.
- Object to part link = the notes' `model_names` first, then the ring-model's `part_ids` (they differ today: Gaps 1).
- Layer rows follow the record's order (bottom to top), as the acceptance says.

## Gaps found in other pieces (reported, not patched)
1. (landed: part ids in ring-model, `?object=` written by the stage) `SceneStage.onPick` writes `part` from `ring-model.nodes[].part_ids[0]` only. Five live nodes have `part_ids: []` (body, band liner, joystick cap, record cap, cell protection) although `part-notes` links them. A click on them removes `part` and no card opens. Cause: `collector/extract/ring_model.py` does not map placement rows with an empty reference (the notes generator's `NO_REF` table does). Also `selectedNode` in SceneStage finds no node for those ids, so nothing highlights. For an object with no line at all, the stage should write `?object=<node name>`.
2. (landed) `__stage.screenPos(name)` is the centre of the part's box. For the curved cell that point is in empty space: a real click there picks nothing (live bundle, 1440 x 900, closed and open). With the whole ring shown, top layers also cover lower ones, so a part below the glass cannot be clicked until its layer is isolated.
3. (landed: `names` option shows the plain name, `hover.png`) No hover callback and no name tag in the stage: the hover tag of the brief is not built.
4. (landed) Notes now come from `usePartNotes()` in `src/data` (`data/content/part-notes.json`); my two fallbacks are deleted.
5. A resource that answers 404 is logged by Chromium as a console error; an empty bundle therefore shows 404 lines in the console. The check counts script errors (`pageerror`, console errors that are not a failed load).
