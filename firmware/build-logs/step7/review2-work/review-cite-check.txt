66: What exists: the Zephyr board `ringrec/nrf54lm20a/cpuapp` (folder `boards/ringrec`: devicetree with every pin of the
67: main chip from `design/ecad/ring/netlist.csv`, the power chip nPM1304 with its two load switches and charger, the SD
68: card on `spi00`, the microphones on `pdm20`, the screen's bus on `spi21`, USB, watchdog, the 1 KB crash record in
69: retained RAM, the flash layout of `design/firmware.md` 9.2; a cell model for the fuel gauge that is NOT THE RING'S
70: CELL (Nordic's 20 mAh sample, a stand-in); a copy of the netlist, which `tools/remote.sh` compares with
71: `design/ecad/ring/netlist.csv` before every run, refusing to run when they differ), the application's settings for it
72: (`app/boards/ringrec_nrf54lm20a_cpuapp.conf` and `.overlay`), the production settings without the debug port
73: (`app/ringrec_production.conf`, `boards/ringrec/ringrec_production.overlay` and `_mcuboot.conf`), and
74: `tools/check_ring_pins.py`, which compares the built devicetree with the netlist. Notes: `docs/board-notes.md`.
75: 
76: How to build it: `tools/build_all.sh` stage 6 (`ring`, then `ring-drivers`, `ring-ram`, `ring-pins`,
77: `ring-pins-broken`, `ring-production`, `ring-production-check`). By hand, in the container:
78: `west build -b ringrec/nrf54lm20a/cpuapp --sysbuild -d <out> app -- -DBOARD_ROOT=/ws/firmware`.
79: 
80: What is unproven: everything that needs a ring. It compiles and its pins match the netlist; no ring has run it. The
81: power part's real file compiles and is on (`CONFIG_RING_POWER_REAL=y`), with a cell model that is NOT THE RING'S CELL;
82: the screen has no panel driver (the memory display stands in); the joystick has no driver. MCUboot is signed with the
83: SDK's debug key ("for debug use only and is not secure"): NOT FOR SHIPPING; the production key is made at the factory
84: step (no key is changed here).
