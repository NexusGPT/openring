# Design review 1: the AI recorder ring, whole design (independent)

Reviewer: judge helper, 2026-11-10, started 21:46 CET. I did not produce this design. Bar (owner): "I need you to fully design EVERYTHING in the ring from the internal, parts, circuit board, etc." and "There should be no ambiguity to build it 100%". Product rule (owner): "The ring shouldn't CONSTANTLY record, only when a long press on it. Then you have a live storing audio". Bar written before the work: any S1 finding means the design is not buildable as written.

Version judged: architecture A5-draft, firmware F3, case C3. The brief names no commit id, so the files are pinned by the SHA-256 list in `hashes-start.txt` (this folder). `requirements.md` carried uncommitted edits when I started (17.10 numbers in its change list; `requirements-uncommitted-diff.txt`); I judged the file as it was on disk.

Severity: S1 = a team would build the wrong thing or cannot build; S2 = a team must ask before building; S3 = unclear or inconsistent, not blocking. File paths are relative to ``.
